# 口腔诊疗风险助手

面向单机构内部测试的 Chrome/Edge 浏览器扩展，用于只读检查 e看牙网页端的口腔病历质量，并将电子病历、患者信息、就诊、收费、影像、处置和文档信息进行跨页面风险分析。

> 当前版本：`0.7.0`。本项目不是 e看牙官方插件，未获得官方接口授权，不得用于自动诊断、自动修改病历或直接认定违规收费、误诊和医疗事故。

## 功能

### 病历质检

- 识别当前病历的主诉、病史、检查、诊断、治疗计划、处置和医嘱；
- 检查核心字段缺失、内容过简、牙位不一致、计划与处置重复等问题；
- 使用本地规则运行，不调用 AI，不修改 e看牙 数据。

### 综合风险分析

自动采集并交叉核对七个模块：

1. 电子病历
2. 患者信息（仅提取质检所需字段）
3. 就诊记录
4. 收费记录
5. 影像记录及文字元数据
6. 处置记录
7. 文档与同意书

主要提示病历完整性、牙位与项目一致性、收费与执行状态、时间逻辑、治疗连续性、同意书和投诉沟通风险。报告按 `严重 → 一般 → 提示` 排序；同级按 `明确矛盾 → 疑似风险 → 数据不足` 排序。

## 安装扩展

1. Chrome 打开 `chrome://extensions/`，Edge 打开 `edge://extensions/`；
2. 开启“开发者模式”；
3. 点击“加载已解压的扩展程序”；
4. 选择本项目目录；
5. 将扩展固定到浏览器工具栏。

## 启动本机 AI 服务

需要 Node.js 18 或更高版本。macOS 可双击 `启动AI服务.command`，或在项目目录运行：

```bash
node server.js
```

服务只监听 `127.0.0.1:8787`。状态地址：

```text
http://127.0.0.1:8787/health
```

## 配置 DeepSeek API

推荐在扩展弹窗展开“DeepSeek API 设置”，输入并保存 API Key。Key保存在当前浏览器扩展的本地存储中，通过本机服务请求 DeepSeek，不发送给 e看牙。

也可以复制 `AI配置示例.txt` 为 `AI配置.txt`，在本机文件中填写：

```text
DEEPSEEK_API_KEY=你的Key
DEEPSEEK_MODEL=deepseek-v4-flash
```

`AI配置.txt`、`.env` 和打包文件均被 Git 忽略，不应上传到仓库。

## 使用流程

### 病历质检

1. 登录 e看牙并进入患者电子病历；
2. 展开需要检查的一份病历；
3. 点击扩展中的“病历质检”。

### 综合风险分析

1. 确认本机 AI 服务已启动，API Key已配置；
2. 在患者页面点击“综合风险分析”；
3. 扩展图标依次显示 `1/7` 到 `7/7`，随后显示 `AI`；
4. 分析完成后自动显示综合报告。

## 隐私与安全

- 只读运行，不调用 e看牙 私有接口，不自动编辑、保存、删除或上传病例；
- 页面采集数据仅暂存在 `chrome.storage.session`，关闭浏览器后清除；
- 手机号、身份证号、姓名和病历号会在本机服务再次脱敏；
- API Key不会写入报告或控制台，但浏览器扩展本地存储不等同于系统钥匙串；
- 正式部署应由机构后端统一管理密钥、权限、日志、审计和数据留存策略；
- 影像模块当前只核对记录、日期、牙位和文字元数据，不分析影像像素。

## 目录说明

```text
manifest.json         Chrome/Edge Manifest V3 配置
popup.*               扩展弹窗与API设置
background.js         自动采集、会话暂存和本机服务通信
content.js            当前病历识别与本地质检
report.js             综合风险报告展示与排序
panel.css             页面侧边面板样式
server.js             本机 DeepSeek 代理与结果校验
启动AI服务.command     macOS 一键启动脚本
AI配置示例.txt         本机配置模板（不包含真实Key）
```

## 已知限制

- 页面结构依赖 e看牙 当前前端 DOM，系统更新后可能需要重新适配；
- “未发现”可能表示页面未加载、时间范围未展开或字段位于其他页面；
- 同意书文件存在不等于已经签署，需人工确认签署人、签名和日期；
- 所有结论仅为记录与流程风险提示，最终判断由具备权限的医务人员完成。
